# /adr — Architecture Decision Record作成

## 用途
重要な技術的決定を記録するADR（アーキテクチャ決定記録）を作成する。

## ADRを書くべきタイミング
- 新しいライブラリ・フレームワークの採用
- DBスキーマの大きな変更
- 認証方式・セキュリティ設計の変更
- マイクロサービス化などアーキテクチャの変更
- パフォーマンス改善のための大きな設計変更

## ADRテンプレート
```markdown
# ADR-[番号]: [タイトル]

## ステータス
- [ ] 提案中  - [ ] 採択  - [ ] 廃止  - [ ] 置き換え済み

## 背景・課題
なぜこの決断が必要になったのか、どんな問題を解決するか。

## 検討したオプション
1. [オプションA]
   - メリット: 
   - デメリット: 
2. [オプションB]
   - メリット: 
   - デメリット: 

## 決定内容
[何を採択するか]

## 採択理由
[なぜこのオプションを選んだか]

## 結果・影響
[この決定によって何が変わるか、将来への影響]

## 更新履歴
- YYYY-MM-DD: 作成
```
