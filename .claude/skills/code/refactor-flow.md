# /refactor-flow — リファクタリングフロー

## 用途
既存コードの品質を向上させるリファクタリングを安全に実施する。

## リファクタリングの鉄則
「機能を変えずに構造を改善する」

## 安全なリファクタリング手順
1. **テスト確認** — 既存テストが通ることを確認する（ない場合は先にテストを書く）
2. **スコープ限定** — 変更範囲を最小限に絞る（1メソッド or 1クラスずつ）
3. **小さなステップ** — 各ステップでテストを実行して確認する
4. **コミット** — 動作する状態でコミットしてからNext Stepへ進む

## リファクタリングパターン
- **Extract Method** — 長いメソッドを小さなメソッドに分割する
- **Replace Conditional with Polymorphism** — 条件分岐をポリモーフィズムで置き換える
- **Extract Class** — 責務が多いクラスを分割する
- **Introduce Parameter Object** — 多すぎる引数をオブジェクトにまとめる
- **Replace Magic Number with Constant** — マジックナンバーを定数化する

## コード臭チェック
- [ ] メソッドが20行以上あるか（Extract Method の候補）
- [ ] クラスが500行以上あるか（Extract Class の候補）
- [ ] 引数が5個以上あるか（Parameter Object の候補）
- [ ] 同じコードが3箇所以上あるか（DRY 原則違反）
